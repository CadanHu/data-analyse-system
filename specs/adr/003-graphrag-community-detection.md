# ADR-003: 引入 GraphRAG 层级社区检测（Map-Reduce 全局搜索）

**状态**：已决定
**日期**：2026-03（对应 PR #1：Implement Hierarchical Community Detection and Map-Reduce Global Search）

---

## 背景

原有 RAG 系统基于向量相似度检索（Local Search），对于"总结性"问题效果差：

- "这份报告的整体结论是什么？" → 向量检索只能返回几个片段，无法跨文档聚合
- "知识库里提到的所有风险有哪些？" → 需要全局视角，不是单点检索

用户的知识库中大量期货研报、日报等文档，这类问题极为常见。

---

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 提升 Top-K 检索数量（如 k=50） | 简单 | Token 爆炸，效果仍然是局部的 |
| 全文检索（FTS5）兜底 | 快速，已有实现 | 关键词匹配，不理解语义 |
| Microsoft GraphRAG：知识图谱 + 社区检测 + Map-Reduce | 真正的全局语义理解 | 实现复杂，构建耗时 |

---

## 决定

**选择方案 3**：实现 Microsoft GraphRAG 论文的层级社区检测架构。

核心组件：
1. **实体 & 关系抽取**：LLM 从文档中抽取三元组（实体-关系-实体）
2. **PageRank**：计算实体重要性
3. **层级社区检测**：Leiden 算法（或 Louvain fallback）构建 L0/L1/L2 层级社区
4. **社区摘要**：对每个社区生成 LLM 摘要（Map 阶段）
5. **Map-Reduce 全局搜索**：按相关度筛选社区摘要，汇总生成最终答案（Reduce 阶段）

触发条件：检测到全局性问题时（"总结"、"整体"、"所有"等关键词）切换为 Map-Reduce 路径，局部性问题仍走向量检索。

---

## 后果

**正面**：
- 总结性和全局性问题回答质量大幅提升
- 知识图谱可视化（ECharts force graph）带来额外的探索性价值

**负面**：
- 知识库构建时间增加（抽取实体 + 构建图 + 社区检测 + 生成摘要）
- L0 社区退化问题（单节点独立社区过多）需要额外的分辨率调优
- 社区摘要需要消耗额外的 LLM 调用，成本更高
- Map-Reduce 路径延迟高于向量检索（多轮 LLM 调用）
